# 설명 점검 — AI 없이 설명할 수 있는지 확인

산출물 기반으로 AI 없이 짧은 시간 안에 답하는 확인 문제에 대비한다. 단계 5와 7, 또는 사용자가 요청할 때 한다. **모범 답을 먼저 보여 주지 않는다.**

1. 기록(`REQUIREMENTS.md`, `HANDOFF.md`, 사용자가 붙여 넣은 구조 설명)에서 질문 3~5개를 낸다. 유형을 섞는다.
   - "이 부분의 가장 큰 약점은 무엇인가?"
   - "요구사항 R#이 바뀌면 어디가 영향을 받는가?"
   - "왜 A가 아니라 B를 골랐나?"
   - "성공 기준이 맞는지 어떻게 확인했나?"
   - `HANDOFF.md`에 구조 그림이 있으면 그 그림의 R·C로 "이게 바뀌면 어느 노드를 고쳐야 하나?"를 최소 하나 넣는다. 그림은 답한 뒤에 보여 준다.
2. 사용자는 질문당 3분 안에, 기록을 보지 않고 답한다.
3. 답마다 세 칸으로 짚는다: **약점을 짚었나 / 파급(무엇이 같이 깨지나)을 설명했나 / 검증·개선 계획을 말했나**. 빠진 칸과, 기록에서 그 답의 재료가 있는 곳(ID)만 알려 준다.
4. 기록에 재료가 없어서 답하지 못한 것은 기록의 빈 곳이다. `REQUIREMENTS.md`나 `HANDOFF.md`에 채우도록 짚는다.

연습 결과 자체는 기록하지 않는다. 4에서 찾은 빈 곳만 해당 표(요구사항 근거, 결정 로그 등)에 채운다.
