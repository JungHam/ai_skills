- 보고서: `YYYY-MM-DD_{기능}.md`
- 캡처: `{기능}_{시나리오}_{결과}.png`. 파일 이름만 보고 무엇을 증명하는지 알 수 있어야 한다.
- 캡처는 보고서에서 **상대 경로 링크**로 건다. 이미지 임베드(`![]()`)를 함께 써도 되지만 링크는 반드시 둔다.

## 캡처 방법

| 대상 | 방법 |
|---|---|
| 웹 UI(내 앱, 관리 콘솔, 워크플로 도구 화면) | 브라우저 자동화나 브라우저 도구로 이동 → 클릭·입력 시뮬레이션 → 스크린샷. 자동화 테스트라면 확인(assert)을 마친 **뒤에** 저장 |
| 모바일 앱 | 시뮬레이터·에뮬레이터 스크린샷 |
| CLI 결과(실행 전후 파일 수, 작업 실행 기록) | 명령 출력을 보고서 코드 블록에 그대로 붙이고, 필요하면 터미널 캡처 |
| 사람만 볼 수 있는 것(받은 메일·메시지) | 사용자에게 캡처를 부탁하고, 받은 파일을 규칙대로 이름 바꿔 저장 |

캡처 전 점검: 화면에 API 키, 비밀번호, 개인 이메일 주소 등이 보이면 가리거나 다른 화면을 쓴다.

캡처 후 점검: 캡처를 **직접 열어 보고** 이름이 말하는 내용이 실제로 보이는지 확인한다. 화면에 드러나지 않는 값(예: 입력칸의 공백)은 보고서에 따로 적는다.

## 규칙

- "확인됨(✅)"은 실제로 본 것에만 쓴다. 못 본 것은 "확인하지 못한 것"에 둔다.
- 실패한 시나리오는 ❌로 남기고 원인과 다음 조치를 적는다. 지우지 않는다.
- 링크가 실제 파일을 가리키는지 마지막에 확인한다(`ls captures/`, 또는 보고서의 링크를 뽑아 하나씩 존재 확인).
- 독립 감사의 지적은 반영하지 않았더라도 지우지 않는다. 감사 뒤 보고서를 고쳤으면 어떤 지적 때문에 무엇을 고쳤는지 "지적별 조치" 표에 남긴다.
