# 요구사항 기록 서식

SKILL.md 모드 D의 상세판. `REQUIREMENTS.md` 하나에 모두 둔다.

## REQUIREMENTS.md 템플릿

```markdown
# 요구사항 기록

- 원본 문서: README.md (과제 안내)
- 시간 제한: 180분 / 시작 HH:MM / 중간 점검 HH:MM, HH:MM

## 요구사항

| ID | 원문 인용(짧게) | 내 해석 | 근거 한 문장 | 확인 방법 | 우선순위 | 상태 |
|---|---|---|---|---|---|---|
| R1 | "사용자는 주문을 CSV로 내려받을 수 있다" | 로그인한 사용자가 자기 주문만, 기간 필터 없이 전체 | 원문에 '자신의'와 기간 언급이 없어 전체로 봄 | 담당자 답 Q2 | 필수 | 확정 |
| R2 | "대량 데이터도 처리" | 10만 행까지 메모리 초과 없이 | 수치가 없어 가정 A1 | 가정 A1 | 필수 | 가정 |

상태: 확정 / 가정 / 확인 중 / 범위 밖

## 담당자 질문

| Q | 관련 ID | 질문(보낸 그대로) | 답(받은 그대로) | 반영 |
|---|---|---|---|---|
| Q2 | R1 | "'자신의 주문'으로 이해했는데, 관리자 전체 조회도 포함인가요?" | "일반 사용자 본인 것만입니다." | R1 확정 |

## 가정

| A | 관련 ID | 가정 | 이유 | 틀렸을 때 영향 |
|---|---|---|---|---|
| A1 | R2 | 대량 = 10만 행 | 원문에 수치 없음, 담당자 답 없음 | 그보다 크면 스트리밍 방식으로 바꿔야 함 |

## 결정 로그

| 시각 | 결정 | 이유 | 감수한 것 |
|---|---|---|---|
| 10:40 | R5(알림 메일)는 범위 밖 | '선택' 표기, 시간 부족 | 가산점 포기 |
```

## 사용자가 해석을 적을 때 쓰는 최소 틀

모드 A로 넘기기 전 사용자에게 안내한다.

```text
R1: "원문 짧게" → 내 해석
R2: "원문 짧게" → 내 해석 ?   (? = 애매함)
```

## 담당자 질문 틀

```text
[관련: R3] "원문 구절"이라고 되어 있는데, A(구체적으로)로 이해했습니다.
B(구체적으로)일 가능성도 있어 확인드립니다. A가 맞을까요?
```

## 제출 문서로 옮기는 법

| 제출 문서 항목 | 가져올 곳 |
|---|---|
| 판단과 근거 | 요구사항 표의 "근거 한 문장" + 결정 로그 |
| 가정 사항 | 가정 표 |
| 남은 한계 | 상태가 "가정"·"범위 밖"인 항목 + 가정 표의 "틀렸을 때 영향" |
