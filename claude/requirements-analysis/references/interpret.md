# 해석 확인 · 누락 점검 · 제약 충돌

## A. 해석 — 입력: 요구사항 문서 (사용자의 해석이 있으면 함께)

**사용자 해석이 없으면 분석 초안을 낸다.** 문서는 한 번 읽고, 기능 요구·비기능 요구·입출력 데이터·제약·완료 기준이 드러나게 항목을 나눈다. 원문을 다시 옮겨 적지 않고 짧게 인용한다.

| ID | 원문(짧게) | 해석 초안 | 구분 | 갈리는 지점 / 확인 질문 |
|---|---|---|---|---|
| R1 | "출근 1편 퇴근 1편 반드시 배치" | 모든 근로자가 근무일마다 왕복 1회씩 | 원문 | — |
| R3 | "버스 노선을 정한다" | 기존 노선표를 고치는 것 | 추론 | 새로 만드는 것일 수도 있음 → "기존 노선을 바꿔도 되나요, 새로 짜나요?" |

구분: 원문 / 추론 / 가정 필요. 끝에 한 줄로 안내한다: "항목마다 확정 · 수정 · 질문으로 넘김을 골라 주세요. 근거 한 문장은 고쳐도 됩니다."

**사용자 해석이 있으면** 그것을 기준으로 판정하고, "일치"가 아니면 확인 질문을 준다. 사용자 해석 형식:

```text
R1: "원문 짧게" → 내 해석
R2: "원문 짧게" → 내 해석 ?   (? = 애매함)
```

| ID | 판정 | 갈리는 지점 | 확인 질문(예시 시나리오) |
|---|---|---|---|
| R3 | 일치 / 갈림 / 부족 | 원문의 어느 단어가 두 가지로 읽히는지 | "같은 이메일로 두 번 가입하면 결과는?" 처럼 **입력 → 결과**를 묻는 질문 |

- **갈림:** 원문이 두 가지 이상으로 읽히고, 사용자 해석이 그중 하나다. 다른 읽기를 한 줄로 보여 준다.
- **부족:** 해석이 경계 상황(빈 값, 중복, 실패, 권한 없음, 0건·대량, 극단값)을 정하지 않았다. 빠진 경계 하나당 질문 하나. 극단값은 "제한이 없으면 극단으로 가면 어떻게 되나"를 묻는다(예: 버스 대수 제한이 없으면 1인 1버스도 허용인가).
- 원문으로 정해지지 않는 질문은 담당자 질문(`stakeholder.md`)이나 가정으로 넘긴다.
- 항목마다 **근거 한 문장**을 남긴다: "R3을 이렇게 해석한 이유는 원문의 '___' 때문이다." 초안에서는 스킬이 쓰고, 사용자가 확정하면서 고친다.

## B. 누락 점검 — 입력: 전체 문서 + 요구사항 목록 (A에서 확정한 것 또는 사용자가 쓴 것)

문서는 한 번 읽고, 빠지거나 넘친 것을 보고한다.

| 구분 | 원문 위치·인용 | 무엇이 빠졌나 / 넘쳤나 | 신호 |
|---|---|---|---|
| 누락 | "3. 제출물 — README에 실행 방법" | 목록에 실행 방법 문서화가 없음 | 필수 신호어("반드시", "필수") |
| 넘침 | (원문 근거 없음) | 목록의 "관리자 대시보드" | 근거 없는 범위 |
| 제외 | "SSO·지도는 고려하지 않음" | 목록에 지도 연동이 있음 | 명시적 제외 |

꼭 훑을 곳: 제출물·문서 요구(README, 실행 방법, 설계 설명, 인계 문서), 테스트 요구, 성능·데이터 크기 조건, **"없는" 제약**(대수·횟수·비용 제한이 없다는 것도 조건), **명시적 제외**("고려하지 마라"), 금지 사항, 평가 기준, 우선순위 표현(필수 / 선택 / 가산점). 넣을지는 사용자가 정한다.

## E. 제약 충돌 점검 — 입력: 제약 목록

제약 목록이 없으면 원문과 담당자 답에서 초안을 뽑아 제시한다(톤 분류는 사용자가 확정). 형식 (결과는 `REQUIREMENTS.md`의 제약 표로):

```text
C1: 무엇을 → 기준(수치 or "없음") / 출처(원문·Q번호) / 톤
```

| 쌍 | 어떻게 부딪히나 (한 줄) | 정해진 우선순위 | 다음 행동 |
|---|---|---|---|
| C1 ↔ C3 | 정류장을 합치면 버스는 줄지만 도보가 길어짐 | 없음 | 꼬리 질문(충돌) / 역제안 / 옵션화 |

- 부딪히는 쌍만 보고한다. 확정되면 `REQUIREMENTS.md` 제약 표의 "충돌 상대 · 우선순위" 칸에 적는다. 충돌 표를 따로 만들지 않는다.
- 우선순위가 정해지지 않은 쌍이 담당자 질문 후보다.
- 수치가 없는 제약("너무 많지 않게")은 그 사실을 적는다. 수치화는 담당자에게 묻거나 옵션화한다.
