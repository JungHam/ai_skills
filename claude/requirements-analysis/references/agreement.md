# 서면 합의문 — 구현 전 관문

발굴이 끝나면 `REQUIREMENTS.md`에서 아래 골격을 채운 초안을 제시한다. 담당자 말 인용과 성공 기준 숫자는 기록에 있는 것만 넣고, 없으면 빈 칸으로 둔다. 사용자가 고쳐 확정하면 `AGREEMENT.md`에 두고, 담당자에게 보내 확인 문장을 받으면 단계 2가 끝난다.

점검할 것:
- 문제에 담당자 말 인용이 있나
- 병목이 하나로 좁혀졌나
- 성공 기준에 지금 값·목표 값·재는 곳이 있나. 숫자가 없으면 "담당자 미정 → 옵션 G#"처럼 처리 방식이 적혀 있나
- 안 만들 것이 적혀 있나
- 세 가지 왜가 채워졌나

한 화면 안에 들어가게 쓴다.

```markdown
# 합의문 v1 (HH:MM, 담당자 확인: Q#)

- 문제: (누가, 무엇 때문에, 얼마나 곤란한가 — 담당자 말 인용)
- 병목: (가장 아픈 한 가지)
- 성공 기준:
  | 지표 | 지금 값 | 목표 값 | 어디서 재나 |
  |---|---|---|---|
- 만들 것:
- 안 만들 것:
- 제약: (C# 목록과 우선순위)
- 세 가지 왜:
  - 진짜 데이터는 어디서 오나:
  - 안 만들면 무엇을 잃나:
  - 만든 뒤 누가 유지하나:
- 담당자 확인 문장: "(받은 그대로)"
```

구현 중 합의 내용이 바뀌면 버전을 올려 고치고(v2), 담당자에게 다시 확인받고, 결정 로그에 "의도 변경"으로 남긴다. 성공 기준은 이 파일이 원본이다. 다른 파일은 "AGREEMENT 성공 기준 1"처럼 번호로 가리킨다.
